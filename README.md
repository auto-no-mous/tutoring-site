# tutoring-site (it-tutor.pro)

Платформа для репетиторов и учеников: каталог с поиском по предмету и цене,
запись на занятия (индивидуальные и групповые), домашние задания, чат,
уведомления на почту и в Telegram, отзывы и статистика, полноценная админка.

Список предметов и направлений подготовки настраивается администратором (не
зашит в код), поэтому сайт подходит для репетитора любого предмета, а не
только информатики, с которой начинался замысел. Подробное описание всей
функциональности по ролям (репетитор/ученик/администратор) — в
[`project_description.md`](./project_description.md); этот файл — про то, как
поднять сайт локально или на сервере.

**Стек:** FastAPI + SQLAlchemy (async) + Alembic + SQLite/PostgreSQL на
бэкенде; Vue 3 + Vite + TypeScript + Pinia + Tailwind на фронтенде. Подробнее
— раздел 9 [`project_description.md`](./project_description.md).

## Быстрый локальный запуск

```
.\run-local.ps1
```

Ставит зависимости, применяет миграции, поднимает backend и frontend каждый в
своём окне PowerShell и открывает сайт в браузере (http://127.0.0.1:5173).
Если зависимости уже установлены — `.\run-local.ps1 -SkipInstall` быстрее.
Остановить — закрыть открывшиеся окна или Ctrl+C в каждом.

Этого достаточно, чтобы пощупать весь функционал, кроме реальной отправки
писем и сообщений в Telegram — по умолчанию они просто пишутся в лог
backend'а (`EMAIL_ENABLED=false`, `TELEGRAM_ENABLED=false` в `.env`). Как
включить их по-настоящему — см. разделы «Почта» и «Telegram-бот» ниже; оба
варианта работают уже сейчас, без выхода в прод.

Скрипт линуксовый/маковский эквивалент не поставляется — на не-Windows
системах поднимайте backend и frontend вручную (см. ниже) в двух терминалах.

## Backend (FastAPI + Poetry)

```
cd backend
poetry install
copy .env.example .env   # при необходимости поменять секреты/SMTP/Telegram/VK
poetry run alembic upgrade head
poetry run uvicorn app.main:app --reload --port 8000
```

Swagger/OpenAPI: http://127.0.0.1:8000/docs — там же полный список эндпоинтов
с телами запросов/ответов, актуальный всегда (генерируется из кода).

## Frontend (Vue 3 + Vite + Tailwind)

```
cd frontend
npm install
npm run dev      # http://127.0.0.1:5173, проксирует /api и /files на backend:8000
npm run build    # продакшен-сборка в frontend/dist
```

## Тесты, линтеры, CI

```
# backend (из backend/)
poetry run pytest              # 77+ тестов
poetry run ruff check .        # линт
poetry run mypy app            # типы (пока не блокирует CI, см. .github/workflows/ci.yml)

# frontend (из frontend/)
npm run test                   # vitest
npm run lint                   # eslint --max-warnings 0
npm run build                  # vue-tsc (типы) + vite build
```

Одноимённый пайплайн гоняется в GitHub Actions на каждый push в `main` и на
каждый PR (`.github/workflows/ci.yml`) — два независимых джоба, backend и
frontend, из тех же команд, что и выше.

## Начальные данные: администратор и справочник предметов

Аккаунт администратора — один на всю систему, создаётся отдельным скриптом
(обычная регистрация формой на сайте создаёт только репетитора/ученика):

```
cd backend
poetry run python -m app.scripts.create_admin --email admin@it-tutor.pro --password ...
```

Повторный запуск с другим email/паролем обновит тот же единственный
администраторский аккаунт, а не создаст второй. Значения можно не передавать
флагами, а прописать `ADMIN_EMAIL`/`ADMIN_PASSWORD` в `.env` — тогда скрипт
подхватит их сам.

Справочник предметов/направлений (раздел 2.1, 4 `project_description.md`)
пустой из коробки — можно наполнить его вручную через админку («Предметы») или
разом накатить стартовый набор (математика, информатика, английский и т.д.,
идемпотентно — повторный запуск ничего не задублирует):

```
poetry run python -m app.scripts.seed_subjects
```

Разослать напоминания о ближайших занятиях (раздел 2.7 `project_description.md`);
нужно запускать по расписанию (cron/systemd timer/Task Scheduler) — планировщик
внутри самого приложения не поднят:

```
poetry run python -m app.scripts.send_reminders
```

## Почта (подтверждение регистрации, сброс пароля)

Что уже работает без всякой настройки: письма подтверждения формируются при
регистрации/смене почты, ссылка сброса пароля — при запросе. Пока в `.env` не
указан SMTP (`EMAIL_ENABLED=false` по умолчанию), они просто пишутся в лог
backend'а вместо реальной отправки — этого достаточно, чтобы руками пройти весь
флоу в деве (взять ссылку из лога и открыть её).

Чтобы письма реально уходили — это можно включить прямо сейчас, деплой на
сервер для этого не нужен, только рабочие SMTP-креды:

1. Заведите почтовый ящик/SMTP-доступ на домене it-tutor.pro (либо любом
   другом, если тестируете) — подойдёт обычный почтовый провайдер (Яндекс 360
   для домена, mail.ru для бизнеса) или транзакционный сервис (Postmark,
   SendGrid, Mailgun — обычно даёт лучшую доставляемость и меньше шансов
   попасть в спам, чем личный ящик).
2. Заполните в `backend/.env`:
   ```
   SMTP_HOST=smtp.example.com
   SMTP_PORT=587
   SMTP_USER=no-reply@it-tutor.pro
   SMTP_PASSWORD=...
   SMTP_FROM=no-reply@it-tutor.pro
   EMAIL_ENABLED=true
   ```
3. Перезапустите backend.

Что зависит от реального деплоя: ссылки в письмах строятся из
`FRONTEND_BASE_URL` — пока это `http://localhost:5173`, письма технически
уходят и работают, но ссылка в них откроется только на вашей же машине. Как
только сайт будет на реальном домене — поменяйте `FRONTEND_BASE_URL` на него
(например, `https://it-tutor.pro`), и ссылки станут рабочими для всех.
Дополнительно для продакшена стоит настроить SPF/DKIM записи у почтового
провайдера — иначе письма будут чаще попадать в спам (это делается на стороне
DNS домена, а не в коде).

Кнопка «Отправить письмо ещё раз» в Настройках (если почта не подтверждена)
дёргает `POST /auth/verify-email/resend` и работает тем же образом.

## Telegram-бот

Бот нужен для двух вещей: привязать аккаунт пользователя к его Telegram
(«Подключить Telegram» в Настройках) и после этого слать туда уведомления
(новая запись, отмена/перенос занятия и т.п., раздел 2.7
`project_description.md`).

Бот работает через long polling (сам опрашивает Telegram API), а не через
webhook — специально выбрано так, потому что polling одинаково работает и на
локальной машине, и в проде: не нужен ни публичный домен, ни HTTPS, только
токен бота. Единственное условие — процесс бота должен быть постоянно запущен
(это и есть тот самый шаг, который по-хорошему делается на сервере — см. ниже).

Как настроить и проверить уже сейчас, локально:

1. В Telegram напишите **@BotFather**, команда `/newbot`, следуйте подсказкам —
   получите токен вида `123456:ABC-...` и `@username` бота.
2. Заполните в `backend/.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC-...
   TELEGRAM_BOT_USERNAME=your_bot_username   # без @
   TELEGRAM_ENABLED=true
   ```
3. Во втором терминале запустите самого бота (отдельный процесс, backend его не
   поднимает сам):
   ```
   cd backend
   poetry run python -m app.scripts.run_telegram_bot
   ```
4. В личном кабинете → «Настройки» нажмите «Подключить Telegram» — откроется
   диалог с ботом по персональной ссылке (`t.me/<bot>?start=<токен>`). Нажмите
   «Запустить» в Telegram, бот подтвердит привязку. Вернитесь на сайт и нажмите
   «Проверить».

Если `TELEGRAM_BOT_USERNAME` не заполнен, кнопка в Настройках честно скажет,
что бот пока не настроен, вместо мёртвой ссылки.

Что по-хорошему делается только при реальном деплое: не сама механика (она уже
работает локально), а её *постоянная доступность* — на сервере скрипт бота
нужно держать под присмотром супервизора, а не в открытом терминале. Для этого
в `docker-compose.yml` есть отдельный сервис `bot` (тот же образ backend'а,
команда заменена на скрипт бота), выключенный по умолчанию через
[profile](https://docs.docker.com/compose/how-tos/profiles/) — чтобы
незаполненный токен не запускал контейнер в бесконечном перезапуске:

```
docker compose --profile bot up -d --build bot
```

Точно так же можно оформить систему напоминаний (`send_reminders.py`) — как
systemd-таймер или cron внутри отдельного контейнера; в `docker-compose.yml`
этого пока нет, добавляется по тому же принципу. Пример systemd-таймера,
если бот и backend уже развёрнуты не через Docker, а напрямую на сервере:

```ini
# /etc/systemd/system/it-tutor-reminders.service
[Unit]
Description=it-tutor.pro lesson reminders

[Service]
Type=oneshot
WorkingDirectory=/opt/it-tutor/backend
ExecStart=/usr/local/bin/poetry run python -m app.scripts.send_reminders
```

```ini
# /etc/systemd/system/it-tutor-reminders.timer
[Unit]
Description=Run it-tutor.pro lesson reminders every 15 minutes

[Timer]
OnCalendar=*:0/15
Persistent=true

[Install]
WantedBy=timers.target
```

```
sudo systemctl enable --now it-tutor-reminders.timer
```

## Docker / продакшен

```
cd backend && copy .env.example .env   # заполнить JWT_SECRET_KEY и остальные секреты
cd ..
docker compose up --build -d
```

Поднимает два контейнера: `backend` (Gunicorn + Uvicorn-воркеры, применяет
миграции при каждом старте через `docker-entrypoint.sh`) и `nginx` (отдаёт
собранный фронтенд и проксирует `/api`, `/files` на backend). Опциональный
третий — `bot` (см. раздел «Telegram-бот» выше), включается флагом
`--profile bot`. SQLite-файл и загруженные файлы живут на именованном томе
`backend_storage` — переживают `docker compose up --build`. Порт 80
публикуется наружу.

**Пошагово, с нуля, на чистом Linux-сервере:**

1. Поставьте Docker и Docker Compose plugin (`docker compose version` должен
   отработать без ошибок).
2. Склонируйте репозиторий на сервер: `git clone <repo> it-tutor && cd it-tutor`.
3. `cd backend && cp .env.example .env`, заполните как минимум
   `JWT_SECRET_KEY` (длинная случайная строка — например,
   `openssl rand -hex 32`) и `FRONTEND_BASE_URL` (реальный домен, например
   `https://it-tutor.pro`); остальное — по разделам «Почта»/«Telegram-бот»
   выше, можно и позже. `cd ..`.
4. `docker compose up --build -d` — соберёт образы и поднимет `backend` +
   `nginx`.
5. Направьте DNS домена на IP сервера, поставьте перед nginx TLS-терминацию
   (см. ниже) — без неё пароли и токены идут в открытом виде по HTTP.
6. Создайте администратора и (по желанию) справочник предметов — те же
   команды, что и локально, но через `docker compose exec`:
   ```
   docker compose exec backend poetry run python -m app.scripts.create_admin --email admin@it-tutor.pro --password ...
   docker compose exec backend poetry run python -m app.scripts.seed_subjects
   ```
7. Проверьте: `docker compose ps` (оба контейнера в статусе `running`; отдельных
   healthcheck'ов в compose-файле нет), `curl http://127.0.0.1/api/v1/health` →
   `{"status":"ok"}`.

**TLS/HTTPS.** В комплекте не настроена — контейнер `nginx` слушает голый
HTTP на 80 порту. Проще всего добавить терминацию TLS перед ним, не трогая
`docker-compose.yml` этого репозитория:
- Отдельный [Caddy](https://caddyserver.com/) или
  [Traefik](https://traefik.io/) контейнер перед `nginx`, который сам
  выпускает и продлевает сертификат Let's Encrypt по домену.
- Либо `certbot` прямо на хосте (вне Docker) + системный nginx/haproxy как
  внешний реверс-прокси перед портом 80 контейнера.

**Обновление после изменений в коде:**

```
git pull
docker compose up --build -d
```

Пересоберёт изменившиеся образы, применит новые миграции (entrypoint
backend'а делает это на каждом старте) и перезапустит контейнеры с
downtime в несколько секунд.

**Бэкап.** Всё, что нужно сохранить — именованный том `backend_storage`
(SQLite-файл `db.sqlite3` + все загруженные фото/файлы):

```
docker run --rm -v it-tutor_backend_storage:/data -v $(pwd):/backup alpine \
  tar czf /backup/it-tutor-backup-$(date +%F).tar.gz -C /data .
```

(имя тома может отличаться в зависимости от имени папки проекта — уточните
через `docker volume ls`).

**Логи:** `docker compose logs -f backend` / `docker compose logs -f nginx`.
Backend логирует одним JSON-объектом на строку вне режима отладки
(`DEBUG=false`) — удобно скармливать любому агрегатору логов без
допарсинга.

**Миграция с SQLite на PostgreSQL** (раздел 9 `project_description.md`) —
поднять Postgres (отдельным сервисом в `docker-compose.yml` или managed
БД), сменить `DATABASE_URL` в конфиге `backend`-сервиса на
`postgresql+asyncpg://user:pass@host/dbname` (убрав override SQLite-пути) и
перезапустить — миграции Alembic отработают на новой БД так же, как на
SQLite, схема не отличается.

## Переменные окружения

Все — в `backend/.env` (шаблон в `backend/.env.example`).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ENVIRONMENT` | `development` | произвольная метка окружения (попадает в Sentry, если подключён) |
| `DEBUG` | `true` | человекочитаемые логи и подробные ошибки; `false` в проде включает JSON-логи |
| `DATABASE_URL` | локальный SQLite-файл | строка подключения к БД (SQLite или `postgresql+asyncpg://...`) |
| `JWT_SECRET_KEY` | небезопасный дефолт | **обязательно сменить в проде** — секрет для подписи JWT |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `30` | срок жизни access-токена |
| `REFRESH_TOKEN_EXPIRE_DAYS` | `30` | срок жизни refresh-токена |
| `SMTP_HOST`/`SMTP_PORT`/`SMTP_USER`/`SMTP_PASSWORD`/`SMTP_FROM` | пусто | SMTP-креды, см. раздел «Почта» |
| `EMAIL_ENABLED` | `false` | `true` — реально слать письма; `false` — только логировать |
| `TELEGRAM_BOT_TOKEN` | пусто | токен бота от @BotFather, см. раздел «Telegram-бот» |
| `TELEGRAM_ENABLED` | `false` | `true` — включить Telegram-канал уведомлений |
| `TELEGRAM_BOT_USERNAME` | пусто | `@username` бота без `@`, для диплинка «Подключить Telegram» |
| `VK_CLIENT_ID`/`VK_CLIENT_SECRET`/`VK_REDIRECT_URI` | пусто | креды VK OAuth-приложения, для входа через VK |
| `FRONTEND_BASE_URL` | `http://localhost:5173` | домен фронтенда — используется в ссылках в письмах |
| `CORS_ORIGINS` | `["http://localhost:5173"]` | список разрешённых origin для CORS (JSON-массив) |
| `ADMIN_EMAIL`/`ADMIN_PASSWORD` | пусто | подхватываются `create_admin.py`, если не передать флагами |
| `RATE_LIMIT_ENABLED` | `true` | лимит запросов на `/auth/*` по IP; выключается только тестами |
| `SENTRY_DSN` | пусто | если задан — ошибки летят в Sentry; пусто = функциональность полностью выключена |

## Что умеет сайт (кратко)

Полное описание по ролям — в [`project_description.md`](./project_description.md).
Здесь — конспект.

**Репетитор:** анкета с фото, форматированным «о себе» (включая вставку
картинок с выравниванием) и красивой ссылкой на профиль (свой ник вместо
UUID); типы занятий (индивидуальные/групповые); расписание с гранулярностью
слотов, перерывом между занятиями, минимальным запасом времени; полный CRUD
по записям, ручные брони, еженедельная регулярность, отмена/перенос без
ограничений (в отличие от ученика); отдельные политики отмены/переноса для
учеников; домашние задания с ручным контролем статуса; личный и групповой
чат; журнал событий с фильтрами; группы подготовки (заявки, зачисление,
посещаемость по каждому ученику); уведомления в Telegram/на почту.

**Ученик:** публичный каталог с фильтром по предмету/цене и подгрузкой по
скроллу; мастер записи (тип занятия → дата → время → подтверждение, время — в
своём поясе плюс МСК); отмена/перенос в рамках политики репетитора;
регулярная запись; заявки в группы; домашние задания (файл или отметка);
чат; статистика с журналом событий; отзывы репетиторам.

**Администратор:** полный CRUD по репетиторам (включая анкету целиком, не
только базовые поля) и ученикам; список занятий по всей платформе с
фильтрами (репетитор/предмет/направление/класс/период) и переносом через тот
же мастер, что у репетитора; управление группами вплоть до передачи другому
репетитору; CRUD справочника предметов/направлений.

**Общее:** JWT-авторизация с автообновлением токена, вход по email+паролю или
через VK, подтверждение email, восстановление пароля, привязка Telegram,
rate limiting и временная блокировка аккаунта при подборе пароля,
светлая/тёмная тема, адаптивная вёрстка, правовые страницы (152-ФЗ).

## Известные ограничения

В форме ручной записи на занятие («Резерв / запись вручную» у репетитора и в
админке) ученик всё ещё указывается по ID — поиск по имени сделан только для
формы выдачи домашнего задания. Календарного виджета нет, списки простые.
Дизайн утилитарный (Tailwind без кастомной темы). Telegram-бот и почта
